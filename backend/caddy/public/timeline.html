02 / INTEROPERABILITY

Reuse the ecosystem’s formats.

FormatBest fitBackend design choice
01 / LeRobot v3 ↗INITIAL SUPPORT · EPISODESMP4 + Parquet + episode metadataFirst export target: aligned video / events with explicit observations. Never invent robot actions.
02 / COCO ↗INITIAL SUPPORT · MASKSPer-frame instance masks in lossless RLESave SAM3-generated masks now; preserve object IDs and frame timing separately.
03 / ASAM OpenLABEL ↗Temporal / multimodal JSONAdd when richer event / object annotation is needed.
04 / RLDS ↗Episodes / steps; TFDS ecosystemConsumer-requested research adapter.
05 / robomimic ↗HDF5 demonstrationsConsumer-requested imitation-learning export.

Initial plan: LeRobot for episodes + COCO for SAM3 masks. OpenLABEL / RLDS / HDF5 remain optional adapters. Processing and exports are planned—not implemented.

Store masks—not just colored overlays.

  • Lossless COCO RLE or PNG; source frame index, timestamp, dimensions, and object ID.
  • Keep model version, prompts, available scores, and review state. Generated masks are not ground truth.
  • COCO is per-frame; preserve temporal IDs and offer YouTube-VIS export if a video-tracking consumer needs it.

Official SAM3 requires CUDA. Plan separate backend compute; iPhone checks indicate capture support, not on-device SAM3 inference.

UMI-inspired, not “UMI compliant.”

  • Adopt the principles: tool-relative video, measured jaw width, synchronized pose, and latency checks.
  • Study the hardware / 3D-printing guides and FastUMI mounts as CAD references—not drop-in reacher parts.
  • Keep our stock reacher, removable iPhone mount, and cable trigger. Add continuous jaw measurement before claiming action-ready data.

UMI is an open research framework, not a formal standard. UMI on Legs and FastUMI demonstrate adoption; market-wide usage is unmeasured. The original pipeline is tested on Ubuntu, not our M1 Mac.

03 / SIMULATION SETUP

Start small. Start with MuJoCo.

Build the simulation harness before testing policy value. Start with a small CPU-based task on the M1 Pro—not foundation-model training.

LOCAL / START HERE

MuJoCo ↗

  • Free, open source; macOS universal build.
  • Simple arm, gripper, rigid objects.
  • Replay / retarget first; small policies next.
REMOTE / LATER

NVIDIA Isaac Sim / Isaac Lab ↗

  • Robotics simulation + learning workflows.
  • Supported NVIDIA RTX host required; not local M1.
  • Consider a compatible rented host only if needed.
  1. Check trajectory reach, timing, and collisions.
  2. Establish robomimic BC on the public Lift PH dataset.
  3. Randomize objects, friction, lighting, and noise.

Simulation validates the tested model only. A borrowed robot or partner lab must confirm real-world transfer. Grass, flexible litter, and contact are especially hard to model.

04 / SPECIFIC BASELINE

Start with BC on robosuite Lift.

Baseline: robomimic feed-forward behavioral cloning (BC), trained on the public Lift proficient-human low-dimensional dataset; evaluate in its matching MuJoCo / robosuite environment.

Available today

  • Public Lift PH dataset and BC implementation.
  • Lift simulation: randomized cube pickup.
  • Small CPU experiment first; pin matching versions and smoke-test on M1.

Then test our data

  • Lift validates the pipeline—not litter-data value.
  • Next: public Can pick-and-place baseline, then a matched litter task.
  • Compare the same BC model with / without task-matched, retargeted demonstrations.

Success gate

  • Held-out task success, drops, collisions.
  • Same compute, splits, seeds; confidence intervals.
  • Video + squeeze events alone do not supply BC actions.

Before reliable pose / jaw labels exist, test outcome prediction on real video instead. Do not add unmatched phone recordings to the Lift dataset or interpret a simulator smoke test as proof of commercial value.

06 / PROJECT TRAIL

Follow the evidence.
Repeat where it matters.

Hover, focus, or tap a node for details and its feedback path. Progress depends on passing each gate—not a calendar.

Define the acceptance spec

  • Choose task, target user, and success metric.
  • Measure phone capabilities and calibration.
  • Agree consent, license, and quality gates.

Gate → observable signals and testable requirements.

Build recording. Review a small pilot.

  • Synchronize streams; retain originals and failures.
  • Check drift, missing frames, and label agreement.
  • Freeze an independent held-out split.

Loop ↺ Capture fails QA → revise the contract and recollect.

Prove model and policy benefit

  • Compare perception and simulated policies with / without our data.
  • Report held-out improvement and uncertainty.
  • Count accepted episodes and review cost.

Loop ↺ No improvement → refine collection / labels before adding volume.

Package for existing tools

  • Version episodes, labels, units, and frames.
  • Validate LeRobot episodes and COCO SAM3 masks together.
  • Round-trip a sample in a consumer loader.

Gate → a partner can load the data without bespoke tooling.

Build a small MuJoCo harness

  • Validate retargeting and jaw-state assumptions.
  • Smoke-test BC / Lift PH; freeze randomized test scenes.
  • Add a sensor only for a measured gap.

Loop ↺ Weak action signal → instrument, recalibrate, and repeat the pilot.

Validate transfer and demand

  • Borrow robot access through a lab / partner.
  • Agree sample acceptance and paid-pilot terms.
  • Scale, refine, or pivot based on evidence.

Loop ↺ Transfer fails → revisit benchmarks and simulation; do not scale yet.
