## Product and architecture

- Registration preference (2026-10-11): require two invite words only, with no legacy-code option or device-name field. Submit without an installation name; the existing backend default label applies. Two rounded word boxes auto-parse a whole pasted phrase into either box, with no auto-submit or silent truncation of extra words. Preserve backend-authoritative validation and input case. Use one **Register** button, omit the initial redundant account message on this sheet, retain failure feedback. Instruction is **Enter the two word invite phrase above**. Large accessibility text stacks boxes. This supersedes the earlier legacy compatibility and editable default-name preferences.

- The authorized experience opens directly to rear-camera capture. A new installation sees collector Home with Continue and Register with invite. Server Addresses and Admin login appear only when the designated private HTTPS admin endpoint is reachable. Returning users reach capture only after backend validation; saved credentials alone are not authorization.
- SwiftUI app, iPhone-only, portrait, iOS 17.2+. `project.yml` is the XcodeGen source of truth; generated `.xcodeproj` is ignored. Regenerate after configuration changes.
- Default to wrapping long UI text rather than truncating it, especially editable server origins: the full hostname and port must remain readable. Server-address fields use vertically expanding multiline input.
- `AccountSession` owns authentication and access state. `LiveCollectorAPI` supplies injectable native networking; `KeychainCredentialVault` stores credentials. `CaptureQueue` persists identity-bound uploads. Camera session work stays off the main thread; observable UI state stays on the main actor.
- Use Apple's `AVCaptureEventInteraction` for either volume button: hold starts recording, release finishes/saves. Onscreen hold control behaves the same. Preserve quick-release-before-start, overlapping holds, cancellation, and background/interruption handling.
- Current capture is video-only MOV, without microphone audio. Rolling pre-grasp buffering, event alignment, and automatic research labels are future work, not implemented features.

## Authentication and trust boundaries

- Physical iPhone and Release builds accept only configurable HTTPS root origins. Debug Simulator builds alone have an explicit local development mode accepting HTTP `localhost` origins, with a localhost-scoped ATS exception absent from device/Release bundles. Never broaden this to LAN/public HTTP or bypass certificate validation. Reject credential-bearing redirects. Private and collector origins must differ, including by port if on one hostname.
- User's test order: manually validate local development without Tailscale first, then the Tailscale-enabled workflow. Coordinate localhost backend/admin setup with Backend Agent; do not weaken the HTTPS pilot's secure cookies for local testing.
- User/admin view policy: actual loss of designated tailnet HTTPS admin reachability dismisses/hides Server Addresses and Admin login. Debug Simulator automatically falls back to the isolated localhost collector, after in-flight operations finish. Local admin discovery cannot grant network-admin UI. Retain the designated HTTPS network configuration separately so reconnection can reveal menus without reassigning origin-bound credentials/queues. Physical/Release keep their HTTPS collector configuration.
- Local-backend selection is independent of network connectivity: toggling it fills BOTH localhost collector/admin fields, keeps the menu open, and waits for Save. A connected admin can select the local admin server; browser handoff requires both the retained network probe and local service identity. Remove the UI phrase "Collectors do not need Tailscale."
- User explicitly deferred authn/authz redesign on 2026-10-11. Implement UI separation only; leave shared-token/session permissions unchanged and do not claim that hiding menus logs a browser out.
- Admin offboarding must distinguish centrally revoked tailnet access, locally disconnected VPN, app UI hiding, and backend session revocation. Current shared-token/stateless-cookie admin auth cannot revoke one admin independently. Do not claim network loss invalidates an existing cookie or that tailnet reachability alone authenticates an administrator. Agree on per-admin backend identity/session enforcement before promising individual session revocation.
- Invite enrollment is backend-authoritative and single-use. Store per-installation access/refresh credentials in origin-scoped Keychain using `WhenUnlockedThisDeviceOnly`, with no iCloud synchronization. Preferences store only non-secret origins. No shared app secret, native passkey enrollment, or App Attest is currently implemented.
- Validate returning access with `/auth/me`; refresh once on `access_invalid`, never on `access_revoked`. Invalid refresh requires administrator help/new invite. Transient failures retain credentials and local captures; honor `Retry-After`.
- Do not automatically retry enrollment or uncertain uploads: lost responses may consume an invite or create a duplicate. Explain these limitations instead of implying idempotency.
- Show Admin login only after the separate private endpoint returns the exact approved service/version JSON identity over HTTPS. Reprobe on foreground, periodically on Home, and before browser handoff; discard late probes after suspension. Reachability is not admin authentication.
- Future public collectors should not require Tailscale. The current private pilot needs authorized tailnet connectivity on test devices. Funnel/public exposure and admin passkeys are separate approval/design decisions, not automatic next steps.
- Keep invite codes, access/refresh tokens, admin credentials, and private fixtures out of repository content, chat messages, screenshots, and tool logs. Fresh test invites require explicit authorization, bounded quotas/lifetime, and coordinated revocation after use.

## Capture durability and backend coordination

- On 2026-10-11 the user accepted two randomly selected BIP-39 English words for pilot invites after discussion of 22-bit guessability. Keep strong installation credentials, hashed invite storage, single-use redemption, expiry, quotas, and throttling. The backend owns word-list validation and case/whitespace normalization; older opaque codes are no longer accepted for new enrollment, without changing existing installations. Do not show live words in screenshots/logs or claim revocation prevents first-use guessing.

- Preserve originals in `Documents/Captures`, including successful uploads, network/auth/quota failures, and uncertain outcomes. Never uninstall/reset the app or erase local captures as routine debugging.
- Queue entries belong to the original collector origin and installation UUID. Changing hosts or re-enrolling must not silently reassign old clips. Corrupt queue metadata is preserved, not overwritten with an empty queue. Files app access is enabled; users should not edit the manifest.
- Uploads are manual foreground multipart requests, field `file`, with a 200 MiB content limit. Persist receipts before treating uploads as sent; poll status using authenticated, trusted endpoints. Backend processing currently creates previews/poster frames, not validated segmentation labels.
- For exact endpoint/error schemas, read current `backend/onboarding.md` from the backend checkout/PR and `ios/TooMuchTrash/CollectorAPI.swift`; coordinate contract changes before implementation rather than maintaining a second schema here.

## Build and validation workflow

- Generate the Xcode project in `ios/`, build/test the `TooMuchTrash` scheme, and discover the currently booted Simulator instead of assuming a remembered device UUID or runtime.
- Simulator Keychain tests require normal simulator ad hoc signing (`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`). Entirely unsigned Simulator hosts cannot validate real Keychain behavior. This does not constitute physical-device signing or distribution.
- Full Simulator coverage includes onboarding, Keychain isolation, contract parsing, durable queues, hold/release races, and Home UI. After tests, explicitly install the freshly built app and relaunch it; visually verify its final state rather than leaving a test-run screen.
- Prefer `xcodebuild`/`simctl` for build and lifecycle operations and supported desktop controls for UI. In Xcode 27 the Simulator window may be hosted by Device Hub (`com.apple.dt.Devices`), not the older Simulator app. Rediscover the surface if bindings go stale.
- Observed Xcode 27 Device Hub clipboard controls are **Edit → Use Shared Clipboard / Get Clipboard / Send Clipboard**. For a user-entered secret, prefer an explicit one-shot transfer to the Simulator rather than assuming Mac paste shortcuts or `simctl pbcopy` will remain synchronized. Diagnose with byte counts only; never print token/clipboard contents. Menu presence is verified, not a guarantee about transfer success.
- Admin dashboard now has Logout in its top toolbar. It calls DELETE `/api/v1/admin/session`, redirects to `/unlock` only after confirmed success, and leaves an error/retry on failure. Backend verified cookie clearing and protected-route denial; this is browser logout, not invalidation of a stolen stateless cookie. User confirmed Send Clipboard worked, local dashboard login succeeded, and the token was manually saved in Simulator Passwords; manual Logout/autofill verification is pending. Device Hub coordinate refresh may fail `noWindowsAvailable` despite readable screenshots; ask the user to refresh rather than claiming the UI action succeeded.
- Admin unlock has an accessible eye Show/Hide toggle, hidden initially and re-masked on submit. Dummy browser checks verified unchanged value and no accidental submission. Never reveal real tokens during agent screenshots/testing; have the user inspect privately. User observed Safari insertion adding a trailing space while the saved Passwords entry was correct. Dev token and running hash matched, with no rotation. Approved generated-token-only safeguard now trims surrounding whitespace on submission, preserving internal characters; dummy regressions passed. Do not generalize this to trimming arbitrary user passwords or claim a confirmed Apple Passwords bug.
- The Simulator cannot establish real rear-camera recording or physical volume-button behavior. State this limitation plainly. Physical testing requires an iPhone, device signing, permission/trust setup, and real button presses/framing/playback checks.
- When reporting completion, lead with outcome and validation evidence. Distinguish automated tests, native live integration, deployed backend checks, and physical validation. Print a high-level remaining-work summary to stdout when requested, and concisely identify user-only steps.
