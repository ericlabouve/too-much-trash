# CAD agent

Read the repository's `AGENTS.md`, the relevant version README, source and review reports before changing CAD. Current source and exact experiment records govern details; historical illustrations and notes do not establish current geometry. Check the actual checkout, status and served directory, preserve concurrent work, and make changes reversible and scoped. Record accepted decisions and verified results in the appropriate version README or review record, with unresolved issues and supersessions; preserve history through Git rather than new archive copies.

## Workspace

Use [cad/workspace.md](../../../cad/workspace.md) for the interface and retention policy. From `cad/`, run `uv sync --frozen` when needed, then `uv run --frozen python cad.py` with:

- `list` to discover versions; `plan v3` (or `--operation check`) to inspect a run without creating files.
- `build v3` or `check v3` to run in a new isolated source snapshot; `--output` may name a new directory; keep custom build/check destinations outside the repository or ignored. Outputs default to ignored `cad/build/`, include input hashes and run status, and are not automatically promoted to tracked exports or the viewer. Direct version scripts still write to historical tracked paths.
- `inventory --git --json build/inventory.json` and `explain <cad-relative-path>` to inspect provenance and advisory classifications. `build-site --versions all --output build/site` builds a clean V1/V2/V3 site; `serve v3 --site build/site --port 8767` serves it on loopback. Use a new site path under `cad/build/` for each build; site output and selective historical restoration share this boundary. Legacy source-tree serving needs restored artifact files.

Use the target version in place of `v3`. The V3 workspace check's successful exit means its mechanical checks passed; read `review/workspace-validation.json` for `checks_passed` and reported phone/cuff overlaps, including thin phones and the incompatible 18/20 mm examples. It does not establish physical fit. Isolated runs are output isolation, not a security sandbox. The interface does not slice or control a printer.

Inventory rules describe provenance, not deletion permission. Generated viewer, manufacturing and job payloads have been removed from current tracking after an explicit audit. `cad/workspace-artifacts.json` records exact paths, sizes and hashes against a pinned Git baseline. Preserve settings, physical outcomes and exact submitted-job identifiers; use `cad.py artifacts list` and `artifacts restore --prefix cad/versions/v3/print/jobs/JOB` to recover historical packages. For a built site add `--site build/site`; restore only selected historical paths so fresh current outputs are not replaced. Consult [the migration audit](../../../cad/artifact-migration.md), including retained input exceptions and baseline availability, before altering retention rules. V3 imports canonical `source/actuator_current` STEP/motion assets and `source/clip_current/clip.stl` as build inputs: an STL or STEP can be source geometry. Before any future Git retention or untracking decision, inspect provenance and consumers, establish reproducible generation and slicer recipes, durable experiment storage and working viewer/test asset delivery. Treat `workspace-policy.json` classifications as advisory; compare geometry and validity rather than assuming files are byte-identical across tool versions. Keep incidental caches, environments and credentials out of Git.

For new files, keep maintained code, explicit configuration/locks, irreplaceable references and required imported geometry in Git. Put routine rebuildable exports, slices, preview buffers and inventory/run reports in ignored build output or the agreed artifact store. Keep human physical observations and exact-job identifiers durable; archive the exact submitted package before dropping its only copy. A generated classification alone never justifies untracking existing files. Inspect `git diff --stat` and staged paths before committing; stage deliberate source/config/evidence changes rather than every file produced by a run. If a new source dependency falls outside current rules, record its purpose and update the inventory policy and isolated snapshot inputs/tests together. Add site-consumed retained records and authored resources to `cad/workspace-retained-assets.json`; freshly generated reports override these retained copies. Test a source-only site without local historical payloads, and test selected historical restoration when changing delivery paths.

Interpret highlighted regions literally. Favor compact load paths, rounded transitions, low-material prototypes and deliberate print orientations without sacrificing functional roots or bore ligaments. ## Validation and handoff

Regenerate affected outputs deliberately after source changes, inspect geometry in 3D and run checks appropriate to the changed part: solid validity, sampled movement, cord/band routing, mount and button envelopes, clearances and assembly/service access. Keep viewer, BOM, instructions, reports and manufacturing exports consistent; label any deliberately stale output. Check all relevant phone/side configurations without suppressing known collisions. The outgoing cord has documented carrier/jaw conflicts in some configurations; local cassette clearance is not universal routing clearance. Preserve 18/20 mm phone conflicts and report any additional overlaps. Nominal rigid motion, animation stroke and sampled routes do not establish safe button force, full-squeeze travel, slack behavior or loaded retention.

For viewer work retain V3's part-following lighting-aware annotations and color/brush/shape/arrow tools, full-width viewport and viewer fullscreen fallback with Escape. Cube arrows rotate 90° on click; dragging is smooth and hover does not rotate. Keep toggleable BOM labels and the hide-other-items checkbox. Keep frozen-frame screen drawing separate from the live component-only drawing tool; screen drawing must allow marks outside geometry. Display printed BOM parts at their common assembly scale and label schematic soft goods. Check the served checkout and cache when a change appears missing. Run the relevant viewer tests for changed behavior.

Distinguish geometric checks, offline slicer estimates, observed printer state, user-reported physical outcomes, and measured fit or strength. Zero supports or a valid solid does not establish successful printing. A start record is not completion; an observed completion is not fit. The current promoted actuator's physical assessment and real camera framing, grip, force, friction and retention remain unresolved. When evaluating a claimed zero-support slice, record settings and actual support/interface toolpaths; recent actuator evidence used automatic supports on and bridge suppression off. After the next actual print containing the selected 35° jaw features, ask: “Did the 35° angled features print successfully without supports?” Ask about sagging, separation and cuff retention where relevant, and record the exact job and feedback. This angle is not a universal printability limit.

For slicing, printer setup or control, also use [bambu-print](../bambu-print/SKILL.md). Preserve immutable job records and use new output directories for revisions. For plate review use `cad/slice_review/` and the printer skill's slice-review guidance, showing actual toolpaths and source hashes. Prior design approval or a reference slice does not itself authorize a print; follow the user's current instruction and printer workflow. The rejected extra two-fastener coupon should not be repeated without direction.
